# 闸口事件湖仓台

码头闸口扫描先落在贴源层，原文照收。建层员选定业务日，按事件字典把扫描收成明细层：进闸、出闸、倒箱。字典里没有的事件码，收成明细前要先定清洗办法；箱号不合法或时间读不出的扫描留在剔除清单，不进明细。

这里不管堆存量，只处理扫描事件怎么分层。

## 未知事件码的清洗

字典认不出的事件码不会让不同批次各收各的。每个业务日的每个未知码只定一次清洗办法：

| 清洗办法 | 收成结果 |
|----------|----------|
| 整条剔除 | 该码的扫描全部进剔除清单，不进明细 |
| 改写为未分类事件 | 该码的扫描进明细，事件记作「未分类事件」，原事件码并排保留 |

- 办法写进字典设置后，本日禁止改口；同一码再提别的办法会被回绝。
- 收成请求带来的清洗办法必须与字典设置一致，偏离时该码记「字典清洗不符」，不落库。
- 两名建层员同时给同一码做清洗时加锁串行：只采纳与字典设置一致的那一笔，另一笔记「字典争用」。
- 字典设置还在保存时，该码暂不准收成。
- 事件码为空的扫描不进未知队列，也不能定清洗办法；收成时直接进剔除清单。

## 页面

- **事件字典**：已登记事件（IN 进闸、OUT 出闸、RS 倒箱）和未知事件分开列出。未知事件写出未知码、扫描条数、剔除条数、改写条数、办法名和本日锁状态。
- **清洗详情**：逐笔写出谁给哪个码提了什么办法、结果（落定 / 一致 / 争用 / 清洗不符 / 禁止改口）和说明。
- **明细层**：并排原事件码与收成后的事件；剔除清单写出原事件码与原因。

## 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/dates` | 业务日列表，含已定办法的码数 |
| GET | `/api/dates/<日期>` | 贴源、明细、剔除清单 |
| GET | `/api/dates/<日期>/dict` | 事件字典列表与清洗详情 |
| POST | `/api/dates/<日期>/dict` | 定未知码清洗办法，body `{"items":[{"code":"XX","method":"reject"}]}` |
| POST | `/api/dates/<日期>/build` | 按字典收成，body 可带 `{"clean_methods":{"XX":"reject"}}` 核对 |

清洗办法可写 `reject` / `rewrite`，也可写中文「整条剔除」/「改写为未分类事件」。

## 种子数据

| 业务日 | 贴源 | 明细 |
